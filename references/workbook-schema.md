# 进销存台账 V1 —— 工作簿字段字典

> 本文件是 `scripts/ledgerlib/schema.py` 的完整字段字典, 与实现一一对应。
> 工作簿即台账: 单个 `.xlsx` 文件, 每张工作表第一行为固定表头, 其余为数据行。
> 参考 it: 业务规则见 [business-rules.md](business-rules.md), 操作流程见 [workflows.md](workflows.md)。

## 0. 全局约定

| 项 | 约定 |
|---|---|
| 数值存储 | 全部数值列以数值写入 Excel; 程序读取一律 `Decimal`(openpyxl 读回的 float 经 `Decimal(str(v))` 还原), 杜绝二进制浮点误差 |
| 数量精度 | 6 位小数 `0.000001` |
| 单价精度 | 4 位小数 `0.0001` |
| 金额精度 | 2 位小数 `0.01` |
| 舍入方式 | `ROUND_HALF_UP`(四舍五入) |
| 尾差处理 | 总额内**最大余数法**逐行分配, 行序=记录ID升序, 平局按下标升序, 保证 Σ分摊 = 总额 |
| 币种 | 默认 CNY(元); V1 不支持多币种 |
| 成本方法 | 月末一次加权平均(公司+SKU 单一成本池, 与仓库无关) |
| 期间 | 自然月, 格式 `YYYY-MM`; 业务日期 `YYYY-MM-DD`; 时间 `YYYY-MM-DD HH:MM:SS` |
| 行主键 | 每表首列 `XX-000001` 递增 ID; 业务单据指纹=期间+单号+明细行号+SKU+仓库(见 E12) |

枚举值(与代码常量一致):

- 记录状态: `正常` / `已更正`(原行被更正保留) / `作废`(重设期初或更正级联)
- 期间状态: `未结账` / `试结账`(仅计算不落盘) / `已结账`
- 成本状态: `已确认` / `待确认`
- 调整类型: `盘盈` / `盘亏` / `报废` / `受控更正`
- 分摊规则: `按数量比例` / `按金额比例` / `逐明细指定`; 分摊状态: `未分摊` / `已分摊`
- 行类型(月末结存): `公司` / `仓库`; 状态: `暂估`(试算) / `已结账`(物化) / `历史`(重开后保留)
- 导入状态: `成功` / `拒绝` / `待确认`

## 1. 元数据(Sheet `元数据`)

台账级固定配置, 由 `init` 写入, 只读(程序维护 `写入次数`)。

| 字段名 | 表头 | 类型 | 说明 |
|---|---|---|---|
| key | 键 | TEXT | 配置键 |
| value | 值 | TEXT | 配置值 |
| remark | 备注 | TEXT | 说明 |

键集合: `公司名称`、`币种`(CNY)、`成本方法`(月末一次加权平均)、
`单价精度`(0.0001)、`金额精度`(0.01)、`数量精度`(0.000001)、
`舍入模式`(ROUND_HALF_UP)、`起始期间`(YYYY-MM)、`台账版本`、`创建时间`、`写入次数`、`台账ID`。

## 11. 月末结存(Sheet `月末结存`)

**计算结果表**: 结账时物化(公司行+仓库行), 状态 `已结账`; 试结账查询不落盘。
重开期间后旧物化行标 `历史` 保留, 重新结账产生新版本行(版本=旧版本+1)。

| 字段名 | 表头 | 类型 | 说明 |
|---|---|---|---|
| period | 期间 | PERIOD | |
| sku | SKU | TEXT | |
| wh | 仓库 | TEXT | 公司行=空 |
| row_type | 行类型 | ENUM | `公司` / `仓库` |
| open_qty | 期初数量 | NUM q6 | 上月期末数量(首期=期初库存) |
| in_qty | 计价入库数量 | NUM q6 | 已确认采购 + 正向调整数量 |
| out_qty | 出库数量 | NUM q6 | 出库流水(销售)数量合计; 损耗数量经 `调整数量` 列单列(口径一致, 示例见 AC8) |
| transfer_net | 调拨净 | NUM q6 | 调入 − 调出(仓库行); 公司行恒 0 |
| adj_qty | 调整数量 | NUM q6 | 正向调整 − 负向调整(公司行为 −损耗, 避免盘盈双重计数) |
| end_qty | 期末数量 | NUM q6 | = 期初 + 计价入库 + 待确认后补 + 调整净 + 调拨净 − 出库(恒等式) |
| open_amount | 期初金额 | NUM m2 | round2(期初数量×单价) |
| in_amount | 计价入库金额 | NUM m2 | 已确认采购金额 + 正向调整计价金额 |
| fee_amount | 附加费用分摊额 | NUM m2 | Σ入库行分摊额 |
| out_cost | 出库成本 | NUM m2 | Σ销售出库成本 + Σ负向调整(损耗)成本(最大余数法分配; 损耗按当月统一加权成本) |
| end_amount | 期末金额 | NUM m2 | = 池金额 − 出库成本(恒等守恒); 校验 |期末金额 − round2(期末数量×加权单价)| ≤ 0.01(E07) |
| avg_price | 加权单价 | NUM p4 | round4((期初金额+计价入库金额+附加费用+已确认成本调整)/(期初数量+计价入库数量)) |
| status | 状态 | ENUM | `暂估` / `已结账` / `历史` |
| version | 核算版本 | INT | 结账版本 |
| updated_at | 更新时间 | DATETIME | 物化时间 |

> **冻结成本公式**: 月末加权单价 = (月初金额 + 本月计价入库金额 + 已确认成本调整额) / (月初数量 + 计价入库数量)。
> 其中"已确认成本调整额"在 V1 实现为 Σ 附加费用分摊(见 §14 脚注②)。
> 期末金额 = 池金额 − 出库成本金额; 期末数量 = 期初 + 计价入库 + 待确认后补 + 调整净 + 调拨净 − 出库。

## 14. 原参考 Excel(库存进销存台账.xlsx, 32 列) → V1 映射

原表为单表平铺(仅表头, 无业务数据), V1 不复刻其平铺结构, 仅将其字段作为来源做映射:

| 原表列 | V1 落点 | 说明 |
|---|---|---|
| SKU | 商品档案.SKU | 主键 |
| 期初库存数量 / 期初单价 / 期初库存金额 | 期初库存.数量/单价/金额 | 首期期初 |
| 期末库存数量 / 期末单价 / 期末库存金额 | 月末结存.期末数量/加权单价/期末金额 | 计算结果 |
| 本期入库数 | 入库流水.数量 | |
| 入库类型 | 入库流水(表本身) | 原表为"采购/退货"枚举; V1 只支持采购入库, 退货延后 V2 |
| 入库批次 | 入库流水.批次号 | 追溯 |
| 入库日期 | 入库流水.业务日期 | |
| 入库批次价 | 入库流水.确认单价 | 成本确认单价 |
| 入库批次调整价 / 入库调整价类型 | 入库流水.备注(程序审计) | 调整动作必须经更正流程留痕, 不写原始平铺列 |
| 实际入库价 | 入库流水.确认单价(更正后) | 更正以独立行+关联链表达 |
| 入库报关单号 / 报关类型 / 入库码 | 入库流水.报关单号/报关类型/入库码 | 仅追溯标识, 不参与计价 |

| 出库日期 | 出库流水.业务日期 | |
| 出库类型(本店销售/多渠道销售/库存处置) | 出库流水.渠道; **`库存处置`→调整流水(盘亏/报废)** | "库存处置"不是销售, 归入库存调整 |

### 口径脚注(冻结, 验收按此理解)

1. **盘盈/正向受控更正按"有计价依据的入库性调整"**: 计入计价入库(数量+金额)。
   冻结公式分母为"月初数量+计价入库数量"(不含调整数量), 这是该公式能精确承接盘盈
   且不引入额外分母变量的唯一方式; 期末数量恒等式另行含调整项。
2. **采购成本更正 = 原行保留(记录状态 `已更正`) + 更正行(新单价/金额, `更正关联ID` 指向原行)**:
   差异体现于计价入库金额; 冻结公式的"已确认成本调整额"在 V1 实现为 Σ附加费用分摊,
   更正通过入库行金额变化进入公式, 不设独立"成本调整"科目。
3. **损耗(盘亏/报废/负向受控更正)按当月统一加权成本**与销售同池分配,
   出库成本 = round2(加权单价×数量), 行级尾差最大余数法吸收。
4. **出库成本列是结果**: 结账时写回销售行(调整流水不写, 汇总在结存表);
   查询一律实时重算, 结账后列值才有效; 重开期间重算覆盖旧值(旧值在备份/操作记录可追溯)。
5. **结账保护为硬约束**: 期间 `已结账` 后任何写入被拒; 重开须 授权标识+原因 并级联后续
   已结账期间; 原物化结存行标 `历史` 保留, 版本递增, 全程可追溯。
