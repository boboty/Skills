# 进销存台账 V1 业务规则（冻结口径 + 实现精度定义）

> 本文档是 V1 的业务规则权威依据。所有程序行为、测试断言、验收判断均以此为准。
> 上篇"冻结业务口径"来自任务书，任何修改必须由业务方（Human）明确决定；
> 下篇"实现精度定义"是任务书要求明确、由实现者确定的确定性规则，同样提交审查，
> 一旦确定即按确定性规则实现，不得在程序内再次解释或变更。

---

## 上篇：冻结业务口径（V1 边界）

### 1. 范围

| 维度 | V1 要求 |
|---|---|
| 企业范围 | 单公司 |
| 仓库范围 | 多仓库 |
| 数量核算 | SKU + 仓库 |
| 成本核算 | 公司 + SKU 统一成本池（所有仓库共享同一月末加权单价） |
| 成本方法 | 自然月、月末一次加权平均 |
| 库存调拨 | 改变仓库数量，不改变公司总数量和总成本 |
| 采购成本 | 必须有明确确认的入库成本；缺失成本依据的入库进入待确认状态，不得静默以零成本入账 |
| 附加费用 | 仅按指定规则分摊（按采购数量比例 / 按采购金额比例 / 逐明细指定金额），尾差处理确定且可复现 |
| 税费 | 不自动判断税费处理口径 |
| 期间管理 | 自然月结账；已结账期间受保护 |
| 币种 | V1 默认人民币（CNY） |
| 计量单位 | 每个 SKU 一个库存基本单位 |
| 退货 | 采购退货、销售退货均延后 V2；不得用普通入库/出库伪装退货 |

明确不属于 V1：FIFO、其他成本算法、多公司、多币种、业务退货、ERP 在线接口、税务申报、会计凭证生成。

### 2. 业务记录与计算结果分离

- 业务流水（入库/出库/调拨/调整/期初）是原始事实（Fact）。
- 库存结存与出库成本是计算结果（Result），由确定性程序从流水重算得到。
- **月末结存不得作为第二套事实独立维护**，必须可从已入账流水完整重算。
- 不允许人工直接覆盖确定性计算得到的销售出库成本。
- 业务记录可追溯；异常数据不擅自补全，报告明确异常。

### 3. 成本计算口径（每个自然月、每个公司级 SKU 成本池）

```
月末加权单价 =
  (月初库存金额 + 本月计价入库金额 + 本月已确认成本调整额)
  ÷
  (月初库存数量 + 本月计价入库数量)
```

- 所有仓库共享相同的公司级 SKU 月末加权单价。
- 仓库数量独立核算。
- 调拨不参与公司级采购入库和销售出库统计。
- 同月销售出库和损耗（盘亏、报废）采用统一月末成本。
- 月初余额由"上月最终结存"衔接；首期由期初库存构成。
- 结账前检查各仓库库存不得出现不允许的负数（入库/出库/调拨/调整实时校验，试结账全量复核）。
- 月末库存数量为零时，不允许留下无依据的库存余额。
- 当期成本发生更正（含历史更正级联）时，必须重新计算受影响结果。
- 零分母、负库存、未确认成本、无法平衡的尾差 → 报告明确异常，不得产生貌似正常的结果。

### 4. 期间控制

| 状态 | 行为 |
|---|---|
| 未结账 | 允许新增和受控更正 |
| 试结账 | 执行成本计算、异常检查与数量金额对账，不落最终结果 |
| 正式结账 | 经用户明确确认后冻结期间（写入结存与核算版本） |
| 已结账 | 普通指令和导入不能直接修改 |
| 受控重开 | 要求明确授权、记录原因、保留原始版本和变更记录 |

- 结账顺序：期间 P 正式结账前，P−1 必须已正式结账（逐月顺序结账）。
- 重开期间 P：级联重开所有后续已结账月份，全部重新核算（按时间顺序），不允许只改历史单元格。
- 每次结账/重开/更正均写入操作记录与版本信息。

### 5. 业务操作口径

- **期初库存**：SKU + 仓库，录入数量与确认单价，金额=数量×单价（精度见下篇）；期初必须全部已确认成本。
- **采购入库**：录入业务日期、期间、单号、明细行号、SKU、仓库、数量、确认单价与金额；支持批量导入；成本更正必须引用原入库行并有依据；附加费用分摊必须绑定到具体入库单明细。
- **销售出库**：录入数量、渠道、订单号、销售价格（及调整依据）；校验指定仓库可用数量；出库成本由月末加权计算，不允许覆盖。
- **仓库调拨**：一笔调拨同时生成调出/调入两侧数量变化，同一调拨单号关联；两侧整体成功或整体失败（原子）；公司层面数量与金额净变化为零；V1 不支持跨日期在途调拨（调拨业务日期两侧相同）。
- **库存调整**：盘盈（必须有明确成本计价依据）/ 盘亏 / 报废 / 录入错误的受控更正；盘亏、报废使用当月统一加权成本。

### 6. 对账勾稽（试结账与正式结账均执行）

1. 分仓：期初数量 + 入库 − 出库 ± 调整 ± 调拨净 = 期末数量（每个 SKU×仓库）
2. 公司总库存数量 = 各仓库库存数量之和
3. 调拨在公司层面数量、金额净变化均为零
4. 公司库存金额与成本变动、出库成本及结存金额相符（金额守恒，见下篇 §3 尾差规则）
5. 上月期末与下月期初一致
6. 业务来源记录不存在重复入账（文件摘要、来源文件+工作表+行号、业务单据+明细行三重防重）

### 7. 导入与自然语言工作流

- 输入：自然语言、`.xlsx`、`.csv`。
- 字段映射显式可见；不确定映射必须要求确认；先预览后提交。
- 同一来源文件重复提交不得重复入账（文件内容摘要去重）。
- 相同业务单据与明细行内容冲突必须阻止或要求人工裁决。
- 部分异常不得悄悄丢弃：必须报告成功、拒绝、待确认记录数量及原因。
- 业务计算程序不调用大模型 API（AI 只负责理解与确认，程序负责确定性计算与写入）。

## 下篇：实现精度定义（确定性规则，审查后生效）

> 任务书要求"必须明确单价、金额计算精度及尾差分配规则"。以下为 V1 实现采用的定义。

### 1. 数值机制

- 全部数量、单价、金额使用 Python `decimal.Decimal`；禁止浮点数参与业务计算。
- 舍入模式：`ROUND_HALF_UP`（四舍五入）。

### 2. 精度

| 量 | 精度 | 说明 |
|---|---|---|
| 数量 | 6 位小数（0.000001） | 录入即量化；期初、业务流水一致 |
| 成本单价 | 4 位小数（0.0001） | 期初单价、采购确认单价、月末加权单价均按此显示与参与计算 |
| 金额 | 2 位小数（0.01） | 所有金额列 |
| 百分比/比例 | 内部使用高精度 Decimal（28 位上下文），仅最终分配金额量化到分 | 避免比例中间舍入 |

### 3. 尾差规则（确定且可复现）

所有尾差分配使用**最大余数法**，行序固定为"记录 ID 升序"，因此结果完全确定、可复现。

**a) 附加费用分摊（三种规则共用）**
- 按数量比例：`金额_i = round2(总附加费 × 数量_i / Σ数量)`，尾差按最大余数法补到分，保证 `Σ金额_i = 总附加费`。
- 按金额比例：同上，以`金额_i / Σ金额`为权重。
- 逐明细指定：用户逐行指定，校验 `Σ指定金额 = 总附加费`，不符则异常（不允许静默改数）。
- 分摊对象：必须绑定到具体采购入库单的明细行（单据+行号），随该入库单进入成本池。

**b) 出库成本（月末加权）分配**
1. `加权单价_4 = round4(成本池总额 ÷ 成本池数量)`（零分母 → 异常"加权单价无依据"）。
2. 每行原始成本 `raw_i = 数量_i × 加权单价_4`（内部高精度，不提前舍入）。
3. 总目标 `target = round2(加权单价_4 × Σ出库数量)`。
4. `Σ round2(raw_i)` 与 `target` 的差额按最大余数法分配到各出库行，使 **`Σ出库行成本 = target` 恒成立**（金额守恒）。
5. 盘亏、报废（损耗）行与销售出库行合并参与同一分配池，使用同一加权单价。

**c) 结存金额与守恒**
- `本月成本池总额 = 月初金额 + Σ计价入库金额 + Σ已确认成本调整金额`（均为已量化 2 位小数金额，直接求和，精确）。
- `期末金额 = 成本池总额 − Σ出库成本（分摊后）`。此式恒等成立，保证"金额守恒"对账永远精确。
- 校验：`round2(期末数量 × 加权单价_4)` 与 `期末金额` 之差 `≤ 0.01`（1 分）；超过 1 分 → 试结账异常"单价精度引起的金额尾差超限"，须人工裁决（不自动抹平）。
- `期末数量 = 月初数量 + Σ计价入库数量 − Σ出库数量`。

**d) 期初**
- `金额 = round2(数量 × 期初单价)`；若用户同时录入金额且 `|录入金额 − 计算金额| > 0.01` → 异常。
- 期初单价录入即量化到 4 位。

**e) 零库存与余额**
- 月末某 SKU×仓库 数量为 0 且金额 ≠ 0 → 试结账异常"零库存存在金额"。
- 公司级 SKU 数量为 0 且金额 ≠ 0 → 同上（公司级亦校验）。

### 4. 负数库存

- 每次出库、调拨调出、盘亏/报废写入时实时校验：目标仓库该 SKU 数量 − 本次数量 ≥ 0，否则拒绝并报"仓库负库存"。
- 试结账按全月净额复核：任一时点不可出现负数（逐笔顺序核对）。
- 例外：无（V1 不允许负库存）。

### 5. 期初与首期

- 首期（台账初始化时指定的起始月）月初数量/金额 = 期初库存合计。
- 后续月份月初 = 上月正式结账的期末（重开级联时重算）。

### 6. 已结账保护

- 任何修改已结账期间流水的请求（录入/导入/更正/重算之外的直改）一律拒绝，返回明确错误。
- 受控重开：需提供授权标识与原因；重开后原结存行保留（状态=历史版本），重算后写入新版本行。

### 7. 版本与追溯

- 每次写操作前自动备份当前台账到 `backups/`（时间戳命名），写失败自动回滚提示。
- 元数据表记录台账版本号、公司、币种、成本方法、精度参数、当前可写期间。
- 操作记录表记录：时间、操作类型、操作人（代理标识）、指令摘要、变更摘要、相关批次/单号。

## 异常清单（试结账/写入必须明确报告，不得自动补全）

| 编号 | 异常 | 触发 |
|---|---|---|
| E01 | SKU 不存在 | 业务行引用未建档 SKU |
| E02 | 仓库不存在 | 业务行引用未建档仓库 |
| E03 | 仓库负库存 | 出库/调出/损耗使某仓库 SKU 数量为负 |
| E04 | 成本缺失（待确认） | 期间内存在待确认采购成本且未获确认；或盘盈缺计价依据 |
| E05 | 计量单位不匹配 | 业务行数量单位与 SKU 基本单位不一致（导入显式映射错误） |
| E06 | 零库存但存在金额 | 月末数量 0 且金额 ≠ 0 |
| E07 | 金额尾差超限 | 单价 4 位舍入导致结存金额与数量×单价差 > 0.01 |
| E08 | 自然月边界错误 | 业务日期与推导期间不一致；跨期分录（V1 不支持） |
| E09 | 文件部分记录异常 | 导入批次内存在拒绝/待确认记录时不得静默丢弃，须汇总报告 |
| E10 | Excel 写入失败 | 写盘异常时回滚并保留备份 |
| E11 | 业务退货输入 | 检测到"退货"语义（负数采购/销售、退货类型标记）→ 拒绝并提示 V1 不支持 |
| E12 | 重复入账 | 文件摘要重复 / 来源行列重复 / 业务单据+明细行冲突 |
| E13 | 结账顺序错误 | 关闭 P 时 P−1 未结账 |
| E14 | 零分母加权单价 | 成本池数量为 0 但存在需计成本的出库/损耗 |
| E15 | 已结账期间修改 | 未授权修改已结账期间 |

## 明确允许的受控更正（未结账期间）

- 采购成本更正：引用原入库行，附更正依据与差异金额，进入成本调整，触发重算。
- 销售价格更正：保存调整依据，不影响出库成本（出库成本不可覆盖）。
- 附加费重新分摊（未结账）：重算分摊金额并校验守恒。
- 录入错误的受控更正：作废原行（保留记录与关联），写入更正行。
