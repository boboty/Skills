# 进销存台账 V1 (Inventory Ledger Skill)

维护**单公司、多仓库**进销存台账: 采购、销售、跨仓调拨、盘盈盘亏报废、
采购附加费用、月末一次加权平均成本计算与期间结账。AI 负责把业务语言翻译成
确定性指令与文件; **一切数值计算与校验由程序完成, 结果确定可复现**。

## 能力边界(V1)

- ✅ 采购入库(成本须明确确认)、销售出库、跨仓调拨、库存调整(盘盈/盘亏/报废/受控更正)、
  采购附加费用分摊(按数量/按金额/逐明细)、自然月末加权平均成本、期间结账/重开(授权+原因)、
  查询与对账、导入幂等防重。
- ❌ FIFO、多公司、多币种、**退货(V1 明确不做)**、增值税/税务、凭证、ERP 集成、Web/数据库。
  用户提出这些 → 明确告知不在 V1 范围, 登记为 V2 需求, 不擅自实现。

## 冻结口径(核心, 详见 references/business-rules.md)

- 成本按**公司+SKU 统一池**, 与仓库无关; 数量按 SKU+仓库。
- 月末加权单价 = (月初金额+本月计价入库金额+已确认成本调整额)/(月初数量+计价入库数量),
  单价 4 位/金额 2 位, ROUND_HALF_UP, 行级尾差最大余数法(行序=记录ID升序)。
- 期末金额 = 池金额 − 出库成本(恒等守恒); 出库成本是**计算结果**, 结账时写回, 禁人工覆盖。
- 业务流水是事实, 只增不删(更正=原行保留"已更正"+关联新行); 结存/成本是结果, 可重算。
- 已结账期间硬保护; 重开须授权+原因, 级联重开后续已结账期间, 版本递增, 历史行保留。
- 异常一律明确报错(E01–E18), 不自动补全; 预览有拒绝行必须向用户报告等裁决。

## 运行环境

- 需要 `python3`(3.9+) 与 `openpyxl`(>=3.1)、`pytest`(仅测试)。安装:
  `python3 -m pip install -r requirements.txt`(或按 README)。
- 所有命令: `python3 <技能路径>/scripts/cli.py <子命令> ...`。
- 相对本文件的位置: `scripts/`(程序) `tests/`(自动化测试) `examples/`(模板与样例)
  `references/`(业务规则/字段字典/工作流)。

## 智能体启动步骤(拿到任务后)

1. **读规则**: 先读 `references/business-rules.md` 确认口径; 操作流程读
   `references/workflows.md`; 字段定义读 `references/workbook-schema.md`。
2. **开台账**: 有现成台账文件则用 `query status` 查看; 没有则 `init`
   (公司名与起始期间必须问清, 不猜)。
3. **建档**: `sku add` / `wh add`(用户给的商品与仓库)。
4. **期初**: `import --type opening --preview` -> `--commit`(数量/单价须用户确认)。
5. **日常**: 采购/销售/调拨/调整/费用文件 -> **先 preview 后 commit**, 逐条展示结果;
   有拒绝行先报告再裁决; 采购成本未确认的行保持"待确认"并**提醒用户提供依据**。
6. **月末**: `query pending` -> `query exceptions` -> 费用分摊预览/执行 ->
   `close dry` 展示数字 -> 用户确认后 `close final` -> `period open` 下月。
7. **更正**: 结账前直接 `cost correct`; 结账后先 `reopen`(要授权+原因)再更正,
   然后依序重新结账(级联)。
8. **任何拿不准的业务含义**(退货、拆单、赠品、负库存、多币种、税费…)一律问用户,
   不自行发挥; 用户确认的决策写入备注/操作记录以便审计。

## 交互式使用引导(面向非技术用户)

与用户的交互方式按以下规则; 业务口径仍以本文件上文与 `references/` 为准, 本节约束"怎么对话", 不改变"算什么"。

### 首次使用: 四种入口
- 用户没有明确业务指令时(如只说"我想开始使用进销存"), 提供四选一并各用一句话说明适用情形, 然后等用户选择, **不擅自初始化台账**:

  1. **体验示例** — 想先看看效果: 用 `examples/demo/` 跑一遍演示数据(或直接展示 demo 输出与账单样例)。
  2. **新建台账** — 从零开始建立自己的台账: 进入分步提问。
  3. **导入已有数据** — 已有 Excel/CSV 业务文件: 先预览再决定导入。
  4. **继续使用** — 已有台账文件: 读取并 `query status` 汇报当前状态, 然后给出下一步建议。

- 用户已有明确业务指令(如"上个月买进一批 X 共 100 件, 单价 10 元")→ **直接执行对应工作流**(见 `references/workflows.md`), 不进入新手向导、不先问无关问题。

### 新建台账: 分步提问
- 按**最少必要信息**分步收集, 一问一答, 每步只问当前需要的一项, 并说明为什么需要:
  1. **公司名称**(台账主体, 必填);
  2. **起始期间**(格式 `YYYY-MM`; 用户不确定时建议当前月, 但必须经确认, 不猜测);
  3. **商品(SKU)与仓库**(用户知道多少问多少, 后续可随时补充);
  4. **期初库存**(数量与单价; 用户说没有则跳过, 不追问)。
- 信息齐备后执行 `init` → `sku add` → `wh add`, 有期初库存则 `import --type opening` 先预览后确认; 每步向用户展示程序返回的结果。

### 帮助与"下一步"
- 用户问"帮助 / 怎么使用 / 下一步怎么做"时: 先 `query status` 查看当前台账状态(或确认无台账), 再结合状态给 1~3 条**具体**建议:
  - 无台账 → 引导初始化(或体验示例);
  - 存在待确认成本 → 催用户提供成本依据;
  - 有未分摊费用 → 提示分摊;
  - 期间未结账 → 走月末循环(§7);
  - 已结账 → 提示开启下月或直接录入日常单据。
- **不重复输出整篇帮助**, 不把说明全文贴给用户。

### 数据准备
- 用户**无需编写 CSV 或执行 CLI**: 由智能体把业务语言或上传的业务文件转换为结构化导入文件(列名与 `references/workbook-schema.md` 一致), 再调用 `scripts/cli.py` 执行。
- 用户上传的业务文件(CSV/XLSX 等)一律先转换/映射并 `--preview`, 把 成功/待确认/拒绝 展示给用户后再决定是否导入。

### 写入纪律与异常
- 所有写入遵守 **预览 → 明确确认 → 提交**(`--confirm`)纪律, 与"纪律"一节一致; 拒绝行必须报告给用户裁决, 不擅自改数重试。
- 出现异常/报错时, 解释**发生了什么、为什么、下一步怎么处理**(给出可操作的建议), 不只输出 E01–E18 错误代码。
- 引导要收敛: 不重复长篇帮助, 熟练用户直接下指令时立即执行, 不被向导拖慢。

## 纪律

- 每个写操作都要求用户明确确认; 展示的是程序算出的确定数字, 不是估算。
- 不要修改原始参考 Excel(用户提供的 `库存进销存台账.xlsx` 只读参考, 在 .gitignore 中)。
- 程序输出一律 JSON(`--json` 为默认), 便于智能体解析; 汇报给用户时转成易读的中文表格。
- 测试: `python3 -m pytest <技能路径>/tests -q` 应全部通过; 改动实现后必须跑通再交付。
